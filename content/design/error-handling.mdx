# Error handling

**Audience:** Designers, Product, QA  
**Purpose:** Help users identify, understand and recover from errors.

## Core guidance

- Identify the field or step containing the problem.
- Describe how to correct the error in plain language.
- Ensure error information is available visually and programmatically.

## Handoff expectation

Designs should communicate relevant states and expected behaviour clearly enough that
development and QA do not need to infer the accessibility requirement after build.

## Specify when errors appear

After submission, show a concise summary linked to each affected field and retain the values already entered. Explain the correction: “Enter a date after today” is more useful than “Invalid value”. Avoid interrupting users with errors before they have finished entering a value. Review server failures separately from input mistakes.
