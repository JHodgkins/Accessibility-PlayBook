# Forms

**Audience:** Designers, Product, QA  
**Purpose:** Design forms with explicit labels, instructions and recoverable error handling.

## Core guidance

- Use persistent visible labels for form fields.
- Place instructions where users encounter them before they are needed.
- Design errors so the affected field and the problem can both be identified.

## Handoff expectation

Designs should communicate relevant states and expected behaviour clearly enough that
development and QA do not need to infer the accessibility requirement after build.

## Handoff a complete recovery path

Annotate persistent labels, required text, hints and example errors. Specify where focus goes after failed submission and how the user reaches the first error. Preserve completed values and permit paste. Group related radio or checkbox options with a meaningful legend. Review the full journey using the component specification.
