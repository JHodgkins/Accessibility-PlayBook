# Organisation requirements

A mature organisation normally defines an internal baseline that explains which
products are in scope, which standards apply and what evidence is expected.

For this POC the example baseline is:

- target WCAG 2.2 Level AA for web experiences;
- consider applicable EN 301 549 requirements;
- use accessible design-system components where available;
- complete manual testing for material user journeys;
- record and triage accessibility defects using user impact;
- route unresolved material risks through the exception process.

This is an illustrative POC baseline, not legal advice.

**Audience:** Product, procurement, engineering, accessibility and risk owners  
**Purpose:** Define the example policy baseline that the playbook operationalises.

For adoption, the accountable sponsor must name in-scope services, the governing
standard versions, suppliers, evidence owners and the authorised exception route.
Review the baseline when product scope or obligations change. Teams must retain
failures in their records even where a release risk has been accepted.
