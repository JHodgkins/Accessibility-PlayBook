# Glossary

**Audience:** All delivery roles  
**Purpose:** Explain the terminology used in this playbook.  
**When to use:** Reading guidance or onboarding a team.  
**Owner:** Accessibility / Content design

**Accessible name**  
The programmatic name assistive technologies use to identify an interface element.

**ARIA**  
Accessible Rich Internet Applications; a WAI specification for adding accessibility semantics where native HTML is insufficient.

**Assistive technology (AT)**  
Hardware or software used to support interaction, such as screen readers, magnifiers and voice-control software.

**Focus**  
The current element receiving keyboard input.

**Reflow**  
The ability for content to adapt to a narrower viewport or increased zoom without loss of information or functionality.

**Semantic HTML**  
Using HTML elements according to their meaning and intended behaviour.

**UAT**  
User Acceptance Testing.

**WCAG**  
Web Content Accessibility Guidelines.

**EN 301 549**  
A European standard containing accessibility requirements for ICT products and services.


**Acceptance criterion**  
A specific observable outcome used to decide whether a feature meets an agreed need.

**Accessibility tree**  
The browser's representation of interface semantics exposed to assistive technology.
It is useful inspection evidence, but does not show the whole user experience.

**Conformance**  
Meeting all applicable requirements of a stated standard within a defined scope.
An automated scan alone cannot establish it.

**Forced colours**  
A display mode in which the system substitutes a user-selected colour palette.

**Inert**  
Unavailable for interaction and assistive-technology navigation, as background content
is intended to be while a native modal dialog is open.

**Landmark**  
A named or typed page region, such as navigation or main content, used for orientation.

**RACI**  
Responsible, Accountable, Consulted and Informed: roles used to clarify work and decisions.

**Roving tabindex**  
A composite-widget technique that gives one item a sequential keyboard focus stop and
moves that stop with arrow keys.

**Risk acceptance**  
A recorded, authorised and time-limited decision about an unresolved barrier; it does
not remove the barrier or establish conformance.

**Severity / priority**  
Severity describes user impact; priority describes when work is scheduled.

**Status message**  
Information about a result or progress that can be communicated without moving focus.

**Regression**  
Previously working behaviour that fails after a change.
