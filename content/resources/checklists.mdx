# Accessibility checklists

## Designer pre-handoff

- Labels and instructions are visible and clear.
- Focus states are represented.
- Error and validation states are designed.
- Responsive behaviour has been considered.
- Colour is not the only means of communication.
- Existing design-system patterns are used where appropriate.

## Developer self-check

- Native semantics are used where possible.
- Keyboard operation works.
- Accessible names match the control purpose.
- Focus movement is intentional.
- ARIA states match visible state.
- Automated checks have been run where useful.

## QA release check

- Acceptance criteria tested.
- Keyboard test complete.
- Relevant screen-reader test complete.
- Zoom/reflow test complete.
- Defects triaged.
- Material unresolved risks recorded.

These prompts support review; they are not proof of conformance. Record results in
the [test template](/resources/templates), investigate failures using the
[severity model](/remediation/severity-model), and review gaps at the
[release gate](/delivery/release-gates).
