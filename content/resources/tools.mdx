# Accessibility tools

The playbook should describe **why** a tool is used, not imply that installing a tool
creates accessibility.

Useful categories include:

- browser accessibility trees and developer tools;
- automated rules engines;
- screen readers such as NVDA, JAWS, VoiceOver and TalkBack where supported by the organisation;
- contrast analysers;
- mobile accessibility inspectors;
- browser zoom and OS magnification;
- CI checks for repeatable regressions.

Tool choice should follow the product's supported platforms and organisational test strategy.

Use the [testing baseline](/standards/testing-baseline) to select combinations and
[method records](/resources/templates) to capture settings and versions. Introduce
one tool with an agreed purpose, representative trial and ownership for maintaining
it. A tool result needs interpretation against the user task before it becomes a defect.
